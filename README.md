# RST Support Bot

**Корпоративный Telegram-бот для регистрации и маршрутизации обращений в службу технической поддержки.**

RST Support Bot помогает сотрудникам быстро оформить заявку через пошаговый диалог: подтверждает принадлежность пользователя к организации, собирает контактные данные, предлагает выбрать категорию проблемы и передаёт структурированное обращение в рабочий Telegram-канал специалистов поддержки.

Проект автоматизирует первичный приём обращений и уменьшает количество уточняющих вопросов со стороны технической поддержки.

## Возможности

### Для сотрудников

- идентификация по ФИО в корпоративном справочнике;
- подтверждение личности одноразовым кодом из email;
- сохранение контактного телефона для повторных обращений;
- подтверждение или обновление ранее указанного номера;
- выбор категории и подкатегории проблемы через интерактивное меню;
- ввод номера AnyDesk для обращений по удалённому доступу;
- описание нестандартной проблемы в свободной форме;
- подтверждение успешной передачи заявки.

### Для службы поддержки

- получение заявок в отдельном Telegram-канале;
- единый структурированный формат обращений;
- автоматическая передача имени и телефона сотрудника;
- указание категории, подкатегории и описания проблемы;
- получение номера AnyDesk, когда он необходим для решения заявки;
- ведение журнала работы бота в консоли и файле.

## Сценарий обработки заявки

```text
/start
   │
   ├── сотрудник уже известен
   │      └── подтверждение телефона
   │
   └── новый сотрудник
          ├── ввод ФИО
          ├── проверка по корпоративному справочнику
          ├── отправка кода на email
          ├── подтверждение кода
          └── сохранение телефона
                 │
                 ▼
       выбор категории и подкатегории
                 │
                 ├── номер AnyDesk
                 ├── текстовое описание
                 └── готовая типовая заявка
                 │
                 ▼
       Telegram-канал технической поддержки
```

Диалог построен на `ConversationHandler`: каждый шаг соответствует отдельному состоянию, а команда `/end` позволяет завершить текущий сценарий.

## Категории обращений

Бот поддерживает семь основных направлений:

| Категория | Примеры обращений |
|---|---|
| Электронная почта | отправка и получение писем, переполненный ящик, архивация, переадресация |
| ПО «Синтез» | установка, настройка, ошибки запуска |
| Компьютер | компьютер не включается, работает медленно, отсутствует интернет |
| Телефония | неисправность телефона, входящие и исходящие звонки, переадресация |
| Принтеры и МФУ | ошибки печати, замена картриджа |
| Удалённый доступ | настройка или восстановление доступа с использованием AnyDesk |
| Другое | выдача доступа и обращения со свободным описанием |

## Технологический стек

**Backend**

- Python 3.9+
- python-telegram-bot 20.7
- Telegram Bot API

**Данные и интеграции**

- SQLite
- SMTP с TLS — доставка кодов подтверждения
- OpenPyXL — импорт справочника сотрудников из Excel
- Requests — отправка заявок через Telegram Bot API

**Инфраструктура**

- Docker
- Docker Compose
- python-dotenv

## Архитектура

```text
rst_bot/
├── bot.py                   # создание приложения и настройка диалога
├── handlers.py              # состояния и обработчики пользовательского сценария
├── database.py              # работа с пользователями и справочником сотрудников
├── email_service.py         # отправка кодов подтверждения
├── send_support_chanel.py   # передача заявок в канал поддержки
├── sync_employees.py        # импорт сотрудников из Excel в SQLite
├── config.py                # переменные окружения и пути к данным
├── logging_config.py        # журналирование в файл и консоль
├── requirements.txt
├── Dockerfile
└── docker-compose.yml
```

Основные части приложения разделены по ответственности:

- `bot.py` создаёт Telegram-приложение, регистрирует обработчики и запускает polling;
- `handlers.py` управляет пошаговым диалогом и временными данными заявки;
- `database.py` сохраняет пользователей и проверяет сотрудников;
- `email_service.py` отправляет проверочный код на корпоративную почту;
- `send_support_chanel.py` формирует итоговое сообщение для специалистов поддержки;
- `sync_employees.py` синхронизирует корпоративный справочник из Excel.

## Хранение данных

Приложение использует две базы SQLite.

### `users.db`

Содержит данные пользователей, которые уже прошли первичную проверку:

- Telegram `chat_id`;
- имя;
- контактный телефон.

### `employees.db`

Содержит корпоративный справочник сотрудников:

- полное имя;
- email.

Справочник формируется из Excel-файла. Для импорта необходимы столбцы `ФИО` и `E-mail`.

## Конфигурация

Скопируйте `.env.example` в `.env` и заполните параметры:

```env
TELEGRAM_TOKEN=your-telegram-bot-token
TARGET_CHAT_ID=your-support-channel-id
FROM_EMAIL=bot@example.com
EMAIL_PASSWORD=your-email-app-password

# Для локального запуска укажите путь к справочнику сотрудников
EXCEL_PATH=/path/to/phonebook.xlsx
```

| Переменная | Назначение |
|---|---|
| `TELEGRAM_TOKEN` | токен Telegram-бота, полученный через BotFather |
| `TARGET_CHAT_ID` | идентификатор канала технической поддержки |
| `FROM_EMAIL` | адрес, с которого отправляются проверочные коды |
| `EMAIL_PASSWORD` | пароль приложения для SMTP |
| `EXCEL_PATH` | путь к Excel-справочнику сотрудников |

Файл `.env` содержит секреты и не должен добавляться в Git.

## Локальный запуск

Клонируйте репозиторий и перейдите в его каталог:

```bash
git clone https://github.com/romatimon/rst_bot.git
cd rst_bot
```

Создайте и активируйте виртуальное окружение:

```bash
python -m venv venv
```

Windows:

```powershell
venv\Scripts\activate
```

Linux/macOS:

```bash
source venv/bin/activate
```

Установите зависимости:

```bash
pip install -r requirements.txt
```

Создайте `.env`, подготовьте Excel-справочник и синхронизируйте сотрудников:

```bash
python sync_employees.py
```

Запустите бота:

```bash
python bot.py
```

## Запуск через Docker

Создайте `.env` и внешний том для постоянного хранения баз данных и журналов:

```bash
docker volume create timoninbot_data
```

Поместите файл `phonebook.xlsx` в каталог `/data` этого тома, затем выполните синхронизацию справочника:

```bash
docker compose run --rm bot python sync_employees.py
```

Запустите бота:

```bash
docker compose up -d
```

Посмотреть журналы:

```bash
docker compose logs -f bot
```

Остановить приложение:

```bash
docker compose down
```

Базы данных и журнал сохраняются во внешнем Docker volume между перезапусками контейнера.

## Безопасность

- токен Telegram и параметры почты передаются через переменные окружения;
- `.env` исключён из Git;
- сотрудник проверяется по корпоративному справочнику;
- первичная регистрация подтверждается кодом, отправленным на email сотрудника;
- SQL-запросы используют параметризованные значения;
- SMTP-соединение переводится в защищённый режим TLS.

Для почты рекомендуется использовать отдельный пароль приложения, а не основной пароль учётной записи.
